Selecting & Modifying the DOM

1. Theory: The Big Picture

Over the first five weeks of our program, we laid a robust foundation for our Agile Task Board. We structured our markup using semantic HTML5, built dynamic layouts using Flexbox and Grid, configured runtime themes with CSS custom properties, and constructed an in-memory data management pipeline using ES modules, arrays, objects, and local storage persistence. However, up to this point, our data state and our visual user interface have operated in parallel rather than as an integrated unit.

The Document Object Model (DOM) is the bridge that connects JavaScript data models to user-visible web interfaces. When a web browser loads dist/index.html, it parses the HTML text into an in-memory tree of live objects. Programmatic DOM manipulation is the practice of inspecting, creating, modifying, and deleting these nodes dynamically using JavaScript.

APPLICATION STATE (Data Layer) DOCUMENT OBJECT MODEL (View Layer) +------------------------------------+ +----------------------------------------+ | dist/assets/js/database/mockDb.js | | dist/assets/js/dom/script.js | | | | | | const tasks = [ | ===> | document.querySelector('.task-list') | | { id: 101, title: 'Auth Fix' } | | element.textContent = task.title; | | ]; | | column.appendChild(taskCardElement); | +------------------------------------+ +----------------------------------------+

In modern web engineering, direct DOM manipulation must follow strict state-driven principles. Rather than arbitrarily editing HTML content across scattered scripts, changes to the DOM should cleanly reflect underlying updates in application data state. In our Kanban project architecture:

  • dist/assets/js/database/mockDb.js owns data storage, array mutation, and localStorage persistence.
  • dist/assets/js/utils/tasks.js handles task operations and validation rules.
  • dist/assets/js/utils/calc.js calculates board metrics (such as total tasks and active counts).
  • dist/assets/js/dom/script.js owns reading DOM nodes, updating text/classes, and programmatically instantiating card elements.
  • dist/assets/js/app.js serves as the application entry point, loading saved data and triggering DOM initialization.

In this session, we will master selector queries, safe node construction, class list toggles, and state-driven rendering pipelines to bridge our JavaScript task models directly to our Kanban board UI.

2. Theory: Semantic Web & DOM APIs

2.1 Element Selection: querySelector vs querySelectorAll

To interact with DOM elements, JavaScript provides modern selection APIs that accept standard CSS selector strings:

  • document.querySelector(selector): Returns the first matching Element node in the document, or null if no match is found.
  • document.querySelectorAll(selector): Returns a static NodeList containing all matching elements. Unlike dynamic HTMLCollections, a static NodeList can be iterated over directly using forEach().
// Target single column list container by ID or class
const todoListContainer = document.querySelector('#todo-column .task-list');

// Target all column headers on the board
const columnHeaders = document.querySelectorAll('.column-header h2');
columnHeaders.forEach(header => {
  console.log(header.textContent);
});

2.2 Text Updates: textContent vs innerHTML

Updating text nodes inside DOM elements requires strict adherence to security and performance standards:

Property Parsing Behavior Security & Performance Profile
textContent Treats input strictly as raw, unparsed plain text. Highly Safe & Fast. Prevents Cross-Site Scripting (XSS) attacks by escaping all characters automatically. Preferred for user-supplied data (task titles, assignees).
innerHTML Parses input string as full HTML markup, constructing new DOM nodes. High XSS Risk. If injected strings contain untrusted user inputs (e.g., <img src="x" onerror="stealCookies()">), malicious scripts execute instantly. Use only for controlled static templates.

2.3 Programmatic Node Creation & Insertion

Instead of concatenating raw HTML strings, production applications build component trees safely using explicit node creation APIs:

  • document.createElement(tagName): Instantiates an unattached DOM element node in memory.
  • element.setAttribute(name, value) / element.dataset.id = value: Assigns HTML attributes and HTML5 custom data-* attributes.
  • element.classList.add('className') / classList.toggle('active'): Safely manages element CSS classes without overwriting existing tokens.
  • parentElement.appendChild(childNode) / parentElement.replaceChildren(...nodes): Inserts or resets child nodes inside a target parent container.
⚠️ Accessibility Consideration (ARIA & Screen Readers)

When programmatically updating dynamic UI regions—such as metric card counts or column item tallies—ensure screen readers announce the changes. Use appropriate ARIA attributes (e.g., aria-live="polite") on containers whose text updates dynamically during runtime.

Step 1: Define Safe Task Card Element Creation (dist/assets/js/dom/script.js)

Open dist/assets/js/dom/script.js and implement the card component factory function:

/**
 * Safely constructs a DOM task card element from a task data object.
 * Uses createElement and textContent to prevent XSS vulnerabilities.
 * 
 * @param {Object} task - The task data model
 * @returns {HTMLElement} The constructed article element node
 */
export function createTaskCardElement(task) {
  // 1. Create root article element
  const card = document.createElement('article');
  card.className = 'task-card';
  card.dataset.id = task.id;

  // 2. Create priority badge dot
  const priorityIndicator = document.createElement('div');
  priorityIndicator.className = `priority-indicator ${task.priority.toLowerCase()}`;
  priorityIndicator.textContent = task.priority.toUpperCase();

  // 3. Create header row with category tag and option button
  const header = document.createElement('header');
  header.className = 'task-card-header';

  const categoryTag = document.createElement('span');
  categoryTag.className = 'category-tag';
  categoryTag.textContent = task.category.toUpperCase();

  const optionsBtn = document.createElement('button');
  optionsBtn.className = 'btn-icon';
  optionsBtn.setAttribute('aria-label', 'Task options');
  optionsBtn.textContent = '⋮';

  header.appendChild(categoryTag);
  header.appendChild(optionsBtn);

  // 4. Create task title heading
  const titleHeading = document.createElement('h3');
  titleHeading.className = 'task-title';
  titleHeading.textContent = task.title;

  // 5. Create footer with assignee details
  const footer = document.createElement('footer');
  footer.className = 'task-card-footer';

  const assigneeSpan = document.createElement('span');
  assigneeSpan.className = 'task-assignee';
  assigneeSpan.textContent = `Assignee: ${task.assignee || 'Unassigned'}`;

  footer.appendChild(assigneeSpan);

  // 6. Assemble complete card hierarchy
  card.appendChild(priorityIndicator);
  card.appendChild(header);
  card.appendChild(titleHeading);
  card.appendChild(footer);

  return card;
}

Step 2: Implement Board Column Rendering Pipeline (dist/assets/js/dom/script.js)

Add the main column rendering function in dist/assets/js/dom/script.js to populate all four status columns ("todo", "in_progress", "review", "done"):

/**
 * Clears and renders all tasks into their respective board columns.
 * 
 * @param {Array} tasks - Array of task data objects from database state
 */
export function renderBoardColumns(tasks) {
  const statuses = ['todo', 'in_progress', 'review', 'done'];

  statuses.forEach(status => {
    // Select column container by status data attribute or selector
    const columnContainer = document.querySelector(`[data-status="${status}"] .task-list`);
    
    if (!columnContainer) {
      console.warn(`Render warning: Column container for status '${status}' not found.`);
      return;
    }

    // Filter tasks matching current column status
    const matchingTasks = tasks.filter(task => task.status === status);

    // Build document fragment for batch insertion (Optimizes DOM reflows)
    const fragment = document.createDocumentFragment();

    matchingTasks.forEach(task => {
      const cardElement = createTaskCardElement(task);
      fragment.appendChild(cardElement);
    });

    // Reset container contents safely and append fragment
    columnContainer.replaceChildren(fragment);
  });
}

Step 3: Implement Dashboard Metrics DOM Updates (dist/assets/js/dom/script.js)

Add the metrics renderer in dist/assets/js/dom/script.js using textContent to update summary cards safely:

/**
 * Updates summary metric card counts on the dashboard header.
 * 
 * @param {Object} metrics - Calculated metric metrics object from calc.js
 */
export function renderDashboardMetrics(metrics) {
  const totalEl = document.querySelector('#metric-total');
  const activeEl = document.querySelector('#metric-active');
  const highEl = document.querySelector('#metric-high');
  const completedEl = document.querySelector('#metric-completed');

  if (totalEl) totalEl.textContent = metrics.total;
  if (activeEl) activeEl.textContent = metrics.active;
  if (highEl) highEl.textContent = metrics.highPriority;
  if (completedEl) completedEl.textContent = metrics.completed;
}

Step 5: Architectural Walkthrough & Debugging Notes

  1. DocumentFragments for Batch Performance: Notice how `renderBoardColumns` uses document.createDocumentFragment(). Appending elements directly to the live DOM one-by-one triggers repeated layout reflows and repaints. Appending items to an off-screen fragment first and making a single replaceChildren(fragment) call executes a single, fast layout operation.
  2. Guarding Selection Targets: Checking if (!columnContainer) prevents null pointer runtime crashes if CSS selectors or HTML IDs change during future refactoring.

/**
 * Highlights task cards matching overdue ID list.
 * @param {Array<number>} overdueTaskIds - Array of task IDs
 */
export function highlightOverdueTasks(overdueTaskIds) {
  const allCards = document.querySelectorAll('.task-card');

  allCards.forEach(card => {
    const cardId = Number(card.dataset.id);
    if (overdueTaskIds.includes(cardId)) {
      card.classList.add('card-overdue');
    } else {
      card.classList.remove('card-overdue');
    }
  });
}

6. Debrief and Homework

Key Takeaways

  1. The DOM is the browser's live, in-memory object representation of parsed HTML text.
  2. Selection APIs (querySelector, querySelectorAll) link JavaScript logic to visual DOM nodes.
  3. Always prefer textContent over innerHTML when handling user-provided strings to prevent XSS security vulnerabilities.
  4. Safe component creation utilizes createElement, classList, and appendChild / replaceChildren.
  5. DOM updates should be strictly state-driven, executing in response to underlying data changes.

Reflective Engineering Questions
