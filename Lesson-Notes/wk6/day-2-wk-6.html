Event Handling & Listeners

1. Theory: The Big Picture

In Session 16, we learned how to select elements and modify the Document Object Model (DOM) programmatically. We built functions like createTaskCardElement() and renderBoardColumns() to translate raw JavaScript task state from dist/assets/js/database/mockDb.js into visual HTML cards inside dist/index.html. However, our application interface remains purely reactive in one direction: it displays data, but it does not yet respond interactively when a user clicks buttons, toggles themes, opens modals, or selects task cards.

Event Handling is the mechanism that breathes life into web applications by allowing JavaScript to listen for and respond to browser events—such as mouse clicks, keyboard presses, form submissions, and structural changes. Without event listeners, user interfaces are inert documents.

USER INTERACTION (DOM Node) EVENT PROPAGATION UI EVENT LISTENER (Module) +-----------------------------+ +---------------------+ +----------------------------+ | Click on .task-card | ------> | Bubbling Phase | ----go> | dist/assets/js/dom/script.js| | or press Enter key | | (Target -> Root) | | board.addEventListener(...) | +-----------------------------+ +---------------------+ +----------------------------+

In our Agile Kanban Task Board architecture, event handling is strictly partitioned inside dist/assets/js/dom/script.js through UI initialization functions like initializeUI(). Rather than scattering inline event handlers (such as onclick="...") across HTML markup—which violates separation of concerns and creates maintenance bottlenecks—we register robust, decoupled event listeners using modern JavaScript APIs.

2. Theory: Semantic Web & Technical Standards

2.1 Registering Listeners with addEventListener

The industry standard method for registering event handlers is element.addEventListener(type, listener, options). Unlike older inline attributes or property assignments (e.g., element.onclick = ...), addEventListener allows multiple independent listener callbacks to be attached to the same event type on a single element without overwriting previous handlers.

// Clean modular listener registration
const themeToggle = document.querySelector("#theme-toggle-btn");
themeToggle?.addEventListener("click", (event) => {
  // Handle theme switching logic
});

2.2 Event Propagation: Bubbling and Target Identification

When an event occurs on a DOM element (for example, clicking a title inside a task card), it does not just fire on that single element. DOM events travel through three distinct phases:

  1. Capturing Phase: The event travels down from the root document object (`document`) to the target element.
  2. Target Phase: The event reaches the exact node where the interaction occurred.
  3. Bubbling Phase: The event bubbles back up from the target element through all its parent ancestors all the way to the root document.

Understanding event bubbling is critical for managing performance in dynamic interfaces like our Kanban board.

2.3 Event Delegation

In our Kanban board, task cards are constantly destroyed, recreated, and re-rendered as tasks are added, updated, or moved across columns. If we attached individual event listeners directly to every single task card element upon creation, rendering performance would degrade, and any newly created cards would lack listeners unless explicitly rebound.

Event Delegation is an architectural pattern where a single event listener is placed on a stable parent container (such as the board container `.board-columns-container`) to manage events triggered by its children. By inspecting event.target or using Element.closest('.task-card'), the parent listener efficiently catches and handles events bubbling up from any current or future child card.

// Event Delegation pattern implemented in dist/assets/js/dom/script.js
board?.addEventListener("click", (event) => {
  const card = event.target.closest(".task-card");
  if (!card || !board.contains(card)) return;

  // Trigger activity drawer open state
  activityDrawer?.classList.add("is-open");
});

2.4 Keyboard Accessibility and Standard Events

Professional web applications must be fully operable via both mouse pointers and keyboards. When building interactive components, listening solely to `click` events alienates keyboard users who navigate via `Tab` and trigger actions using `Enter` or `Spacebar`.

  • click: Fires on mouse clicks, touch taps, and programmatic activations.
  • keydown: Fires when a key is pressed down. Developers must check event.key === 'Enter' || event.key === ' ' to support keyboard accessibility.
  • submit: Fires on form elements when saved or submitted, allowing developers to call event.preventDefault() to intercept standard page reloads and process data via JavaScript.

Step 1: Analyzing UI Event Listeners (dist/assets/js/dom/script.js)

Examine how initializeUI() wires up global interface interactions using safe optional chaining and event delegation:

function initializeUI(documentRef = document) {
    const htmlRoot = documentRef.documentElement;
    const themeToggle = documentRef.querySelector("#theme-toggle-btn");
    const activityDrawer = documentRef.querySelector("#activity-drawer");
    const modal = documentRef.querySelector("#task-modal");
    const board = documentRef.querySelector(".board-columns-container");

    themeInitialiser(documentRef);

    // 1. Theme Toggle Click Listener with localStorage persistence
    themeToggle?.addEventListener("click", () => {
        const isDark = htmlRoot.getAttribute("data-theme") === "dark";
        if (isDark) {
            htmlRoot.removeAttribute("data-theme");
        } else {
            htmlRoot.setAttribute("data-theme", "dark");
        }
        try {
            localStorage.setItem("theme", isDark ? "light" : "dark");
        } catch (error) {
            console.error("[Theme] Unable to save the selected theme.", error);
        }
    });

    // 2. Hamburger Navigation Toggle
    documentRef
        .querySelector("#hamburgerMenu")
        ?.addEventListener("click", () => {
            documentRef.querySelector("#navbar")?.classList.toggle("show");
        });

    // 3. Modal Dialog Open & Close Listeners
    const closeModal = () => {
        if (modal) modal.style.display = "none";
    };
    documentRef
        .querySelector("#open-modal-btn")
        ?.addEventListener("click", () => {
            if (modal) modal.style.display = "flex";
        });
    documentRef
        .querySelector("#modal-close-btn")
        ?.addEventListener("click", closeModal);
    documentRef
        .querySelector("#modal-cancel")
        ?.addEventListener("click", closeModal);

    // Backdrop click detection
    modal?.addEventListener("click", (event) => {
        if (event.target === modal) closeModal();
    });

    // 4. Activity Drawer Close Listener
    documentRef
        .querySelector("#drawer-btn-close")
        ?.addEventListener("click", () => {
            activityDrawer?.classList.remove("is-open");
            activityDrawer?.setAttribute("aria-hidden", "true");
        });

    // 5. Event Delegation: Opening Activity Drawer on Task Card Click
    board?.addEventListener("click", (event) => {
        const card = event.target.closest(".task-card");
        if (!card || !board.contains(card)) return;
        activityDrawer?.classList.add("is-open");
        activityDrawer?.setAttribute("aria-hidden", "false");
    });

    // 6. Keyboard Accessibility Delegation for Task Cards
    board?.addEventListener("keydown", (event) => {
        if (
            (event.key === "Enter" || event.key === " ") &&
            event.target.matches(".task-card")
        ) {
            event.preventDefault();
            activityDrawer?.classList.add("is-open");
            activityDrawer?.setAttribute("aria-hidden", "false");
        }
    });
}

Step 2: Analyzing Form Submission Event Handling (dist/assets/js/dom/script.js)

Examine how initializeTaskBoard() intercepts standard form submission events to prevent page reloads and process new task data:

function initializeTaskBoard({ getTasks, createTask }, documentRef = document) {
    const board = documentRef.querySelector(".board-columns-container");
    const form = documentRef.querySelector("#task-form");
    const errorMessage = documentRef.querySelector("#task-form-error");

    renderBoard(getTasks(), documentRef);

    if (form) {
        form.addEventListener("submit", (event) => {
            // Prevent default browser form submission (page reload)
            event.preventDefault();
            
            const formData = new FormData(form);
            const task = createTask({
                title: formData.get("title"),
                category: formData.get("category"),
                priority: formData.get("priority"),
                desc: formData.get("description"),
                assignee: "Unassigned",
                status: "todo",
            });

            if (!task) {
                if (errorMessage) {
                    errorMessage.textContent = "Please enter valid task details.";
                }
                return;
            }

            if (errorMessage) errorMessage.textContent = "";
            form.reset();
            documentRef.querySelector("#task-modal").style.display = "none";
            renderBoard(getTasks(), documentRef);
        });
    }

    return board;
}

Step 3: Architectural Walkthrough & Debugging Notes

  1. Preventing Default Form Actions: Calling event.preventDefault() inside the form `submit` listener stops the browser from executing its native HTTP GET/POST reload behavior, allowing our JavaScript application to manage data state asynchronously.
  2. Using `event.target.closest()`: When implementing event delegation on the board container, child elements (like the category tag or priority indicator) are clicked instead of the article itself. closest('.task-card') traverses upward from the click target to find the nearest ancestor matching `.task-card`, ensuring reliable interaction regardless of where inside the card the user clicks.

6. Debrief and Homework

Key Takeaways

  1. Event listeners registered via addEventListener provide clean, modular interaction management without inline markup coupling.
  2. Event propagation consists of capturing, target, and bubbling phases; events bubble upward from target nodes to the root document.
  3. Event delegation attaches a single listener to a stable parent container, using event.target.closest() to handle dynamic child elements efficiently.
  4. event.preventDefault() stops native browser actions (such as form reloads), while event.stopPropagation() halts event bubbling.
  5. Accessibility requires combining mouse clicks with keyboard event listeners (`keydown` checking for `Enter` and `Spacebar`).

Reflective Engineering Questions

  1. Why is event delegation significantly more performant than attaching individual event listeners to every task card on a large board?
  2. What is the exact difference between `event.target` and `event.currentTarget` inside an event listener callback?
  3. Why must we call `event.preventDefault()` inside a form submit event listener?
