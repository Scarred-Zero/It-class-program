2. Theory: JavaScript Syntax, Scope & Data Types

2.1 Modern Variable Declarations: `let` vs `const`

Historically, JavaScript relied on the var keyword for variable declarations. However, var suffers from confusing function-scoping rules and hoisting anomalies that introduce subtle bugs. Modern ES6+ JavaScript replaces var with two block-scoped declarations:

  • const (Constant): Declares a variable whose reference cannot be reassigned. In modern engineering, const is the default choice for all variables, functions, and imported modules unless reassignment is explicitly required. Note: Mutating properties inside an object or pushing items into an array declared with const is permitted, but reassigning the variable identifier itself is forbidden.
  • let (Mutable Variable): Declares a variable whose value can be reassigned later in execution (e.g., counters, active filter states, loop iterators).
/* Modern Variable Scope Standards */
const MAX_TASK_TITLE_LENGTH = 100; // Cannot be reassigned
let activeFilter = 'all';          // Can be reassigned during runtime

activeFilter = 'pending';          // Valid
// MAX_TASK_TITLE_LENGTH = 150;  // Throws TypeError assignment to constant variable

2.2 JavaScript Data Types

JavaScript is a dynamically typed language, meaning variables do not have explicit type definitions attached to them at compile time. Data types are categorized into two primary groups:

Category Data Types Description & Examples
Primitives String, Number, Boolean, Null, Undefined, Symbol, BigInt Immutable data stored directly in memory (e.g., const title = "Fix Bug";, const priority = 3;, const isDone = false;).
Reference Types Object, Array, Function Mutable collections or reference pointers stored in heap memory (e.g., task objects, column lists).

2.3 Operators and Strict Equality

When writing conditional logic for our task board, always use **strict equality operators** (=== and !==) instead of loose equality operators (== and !=). Loose equality performs silent type coercion, which leads to unexpected runtime bugs (e.g., "0" == 0 evaluates to true, whereas "0" === 0 correctly evaluates to false).

2.4 Browser Console Debugging Tools

Mastering the browser developer console is essential for debugging asynchronous web apps:

  • console.log(): Outputs general debugging messages.
  • console.table(): Formats arrays of objects or complex dictionaries into clean, readable tabular view.
  • console.error() / console.warn(): Highlights error states or potential runtime warnings in red/yellow.
  • debugger;: Pauses execution inside the browser debugger breakpoint engine automatically when encountered.

// 4. Task Validation Utility Function
function validateTaskInput(title, category, priority) {
  // Use strict inequality and data type checks
  if (typeof title !== "string" || title.trim().length === 0) {
    console.error("Validation Error: Task title must be a non-empty string.");
    return false;
  }

  if (title.trim().length < 3) {
    console.warn("Validation Warning: Task title is extremely short.");
  }

  const validCategories = ["frontend", "backend", "database", "devops"];
  if (!validCategories.includes(category)) {
    console.error(`Validation Error: Invalid category '${category}'.`);
    return false;
  }

  const validPriorities = ["low", "medium", "high"];
  if (!validPriorities.includes(priority)) {
    console.error(`Validation Error: Invalid priority '${priority}'.`);
    return false;
  }

  console.log("%c✓ Task Validation Passed Successfully!", "color: #10b981; font-weight: bold;");
  return true;
}

// Test validation function immediately in console
const testResult = validateTaskInput("Setup PostgreSQL DB", "database", "high");
console.log(`Test Validation Result: ${testResult}`);

Step 2: Architectural Walkthrough & Debugging Notes

  1. Why `const` is prioritized: Notice how `APP_NAME`, `API_VERSION`, and `initialTasksDatabase` are declared with const. Even though items inside `initialTasksDatabase` will later be added or removed, the array reference itself remains constant, protecting against accidental reassignment bugs.
  2. Console Grouping: Using console.group() and console.groupEnd() keeps startup diagnostics organized in the browser console, separating initialization logs from runtime events.

Task Requirement

Write a utility function in js/app.js named formatTaskSummary(taskObj) that takes a task object and returns a formatted summary string using template literals (backticks ``).

Requirements:

  1. The function must extract properties (title, category, priority, assignee) from the passed task object.
  2. It must return a formatted string in the following format: [CATEGORY] Task Title (Priority: HIGH) - Assigned to: Name.
  3. Test your function by passing one of the mock tasks from initialTasksDatabase and logging the result using console.log().

Solution Code

/* Classwork Solution: Task Summary Formatter */
function formatTaskSummary(taskObj) {
  // Destructure properties from the task object
  const { title, category, priority, assignee } = taskObj;

  // Convert category and priority to uppercase for clean display formatting
  const formattedCategory = category.toUpperCase();
  const formattedPriority = priority.toUpperCase();

  // Return formatted string using template literals
  return `[${formattedCategory}] ${title} (Priority: ${formattedPriority}) - Assigned to: ${assignee}`;
}

// Test the formatter against our first initial task
