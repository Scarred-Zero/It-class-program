Module: Web Architecture & Semantic HTML5

1. Theory: The Big Picture

Before writing a single line of production code, a software engineer must possess a robust mental model of the environment in which their applications operate. The modern web is fundamentally built on the Client-Server Architecture[cite: 1].

When a user interacts with a web application, they act as the client, typically through a web browser. The client requests resources (such as HTML documents, stylesheets, or JSON data) from a remote machine known as the server. This data exchange is governed by the HTTP and HTTPS (Hypertext Transfer Protocol / Secure) standards[cite: 1].

[Textual Diagram: The Request-Response Cycle]

[ Client / Browser ] --- (1) User types URL & hits Enter ---> [ DNS Server ]
[ DNS Server ] --- (2) Returns IP Address (e.g., 104.21.5.14) ---> [ Client / Browser ]
[ Client / Browser ] --- (3) HTTP GET Request ---> [ Web Server ]
[ Web Server ] --- (4) HTTP Response (200 OK + HTML Payload) ---> [ Client / Browser (Renders UI) ]

Understanding the DNS (Domain Name System) resolution and the HTTP request/response cycle is non-negotiable for full-stack developers[cite: 1]. Every backend API endpoint, dynamic user interface, and cloud deployment strategy you will build in the coming weeks relies entirely on the precise manipulation of these HTTP transactions.

2. Theory: Semantic Web

Hypertext Markup Language (HTML) provides the structural skeleton of web documents. Historically, web developers relied heavily on generic container tags (like <div> and <span>), leading to documents that were visually functional but programmatically meaningless—a practice often referred to as "div soup."

Modern engineering standards demand the use of Semantic HTML5[cite: 1]. Semantic tags convey the exact meaning and role of the enclosed content to the browser, search engine crawlers, and assistive technologies.

Core Semantic Document Structures

Instead of relying on generic wrappers, we use dedicated structural tags[cite: 1]:

  • <header>: Represents introductory content, typically containing headings, logos, or primary navigation[cite: 1].
  • <main>: Defines the primary, unique content of the document. There should be only one visible <main> element per page[cite: 1].
  • <article>: Represents a self-contained, independent piece of content that could be distributed on its own (e.g., a blog post, a user review, or a specific job role on a CV)[cite: 1].
  • <section>: Groups thematically related content, usually introduced by its own heading.
  • <footer>: Contains structural closing elements, such as copyright data, author information, and secondary navigational links[cite: 1].
Industry Relevance: Semantic HTML directly impacts Accessibility (A11y) and Search Engine Optimization (SEO). A screen reader used by a visually impaired user can instantly navigate to a <nav> or <main> tag, bypassing repetitive header content. A search engine interprets an <article> as high-value content compared to a generic <div>.

4. Lab: Guided Coding

In this lab, we will translate theory into practice by constructing a professional CV layout using strictly semantic HTML5 markup[cite: 1]. At this stage, we are engineering raw structure—there is no CSS attached, meaning the browser will render it using standard, unstyled document flow.

Create a file named index.html in your VS Code workspace and write the following code:

<!DOCTYPE html>
<html lang="en">
<head>
    <!-- Metadata for the browser and search engines -->
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <meta name="description" content="Professional CV for an IT Software Engineering Student">
    <title>Jane Doe | Software Engineer</title>
</head>
<body>

    <!-- Document Header: Identity and Navigation -->
    <header>
        <h1>Jane Doe</h1>
        <p>Full-Stack Software Engineering IT Student</p>
        <nav>
            <ul>
                <li><a href="#summary">Summary</a></li>
                <li><a href="#experience">Experience</a></li>
                <li><a href="#education">Education</a></li>
            </ul>
        </nav>
    </header>

    <!-- Document Main: Core Content -->
    <main>
        
        <!-- Thematic Section: Professional Summary -->
        <section id="summary">
            <h2>Professional Summary</h2>
            <p>
                Detail-oriented Computer Science student seeking Industrial Training. 
                Passionate about web architecture, semantic markup, and building scalable 
                backend systems.
            </p>
        </section>

        <!-- Thematic Section: Work Experience -->
        <section id="experience">
            <h2>Work Experience</h2>
            
            <!-- Article: Independent self-contained unit of information -->
            <article>
                <h3>Backend Development Intern</h3>
                <p><strong>Company:</strong> Tech Solutions Ltd. | <strong>Dates:</strong> Jan 2026 - Present</p>
                <ul>
                    <li>Assisted in architecting RESTful APIs using Python.</li>
                    <li>Drafted technical documentation for client-server data flow.</li>
                </ul>
            </article>
        </section>

        <!-- Thematic Section: Education -->
        <section id="education">
            <h2>Education</h2>
            <article>
                <h3>B.Sc. Computer Science</h3>
                <p><strong>Institution:</strong> State University of Technology | <strong>Expected:</strong> 2027</p>
            </article>
        </section>

    </main>

    <!-- Document Footer: Closing Data -->
    <footer>
        <p>&copy; 2026 Jane Doe. Built for the Practical Software Engineering IT Program.</p>
        <p>View my projects on <a href="https://github.com" target="_blank">GitHub</a>.</p>
    </footer>

</body>
</html>

Debugging and Workflow Notes

Right-click the index.html file in your editor and select "Open with Live Server". Your default browser will launch, rendering the document. Notice how the browser natively interprets the structural hierarchy of <h1> through <h3> tags, and how the anchor tags (<a href="#experience">) allow immediate page routing to specific section IDs.
