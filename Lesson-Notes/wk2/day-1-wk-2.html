1. Theory: The Big Picture

Throughout Week 1, we constructed robust, structural documents using semantic HTML5. However, raw HTML is strictly structural. To transform a raw document into a professional interface—such as the Agile Task Board (Kanban-Style) you have chosen for your Capstone[cite: 1]—we must introduce a new language: Cascading Style Sheets (CSS3).

CSS is based on a foundational software engineering principle: Separation of Concerns. HTML handles the data and structure, while CSS handles the presentation and layout. The primary mechanism CSS uses to apply styles is the CSS Rule, which dictates exactly how the browser's rendering engine should paint the DOM tree onto the screen[cite: 1].

[Textual Diagram: Anatomy of a CSS Rule] selector { property: value; /* This is a declaration */ property: value; } h1 { color: red; font-size: 2rem; }

Because multiple CSS rules might target the exact same HTML element, the browser needs a conflict-resolution system. This system is known as The Cascade[cite: 1]. The Cascade determines which styles "win" based on three factors: Source Order (code written further down overrides code above it), Importance (the !important flag), and most crucially, Specificity[cite: 1].

2. Theory: Semantic Web (Selectors & Specificity Calculation)

In a large application like our future Agile Task Board, which involves dynamic DOM manipulation and real-time client-state updates[cite: 1], you will have hundreds of UI elements. Writing targeted, performant CSS requires mastering Modern CSS Selectors and the mathematical Specificity Calculation[cite: 1].

Modern CSS Selectors

  • Element Selector (h1, p, article): Targets all instances of a specific HTML tag.
  • Class Selector (.task-card): Targets any element containing the specified class attribute. This is the workhorse of modern web development.
  • ID Selector (#main-nav): Targets a single, unique element. ID selectors are extremely powerful but should be used sparingly due to their high specificity.
  • Descendant Selector (.column .task-card): Targets elements nested inside other elements.

Specificity Calculation Engine

Specificity is calculated via a four-tier point system: (Inline Styles, IDs, Classes/Pseudo-classes, Elements)[cite: 1].

[Textual Diagram: Specificity Scoring] Selector: Score (Inline, ID, Class, Element) --------------------------------------------------------------- h1 (0, 0, 0, 1) = 1 .header-title (0, 0, 1, 0) = 10 nav ul li a (0, 0, 0, 4) = 4 #user-profile (0, 1, 0, 0) = 100 .board .column .card h3 (0, 0, 3, 1) = 31

If two rules conflict, the browser compares their specificity scores. A score of 100 (an ID) will always override a score of 31 (classes and elements). This is why engineers prefer using Class Selectors—they keep specificity low enough to be easily overridden when the state changes (e.g., when a task moves from "Pending" to "Completed").

Finally, consider Inheritance[cite: 1]. Some CSS properties naturally flow down the DOM tree. If you set font-family on the <body>, all children inherit it. However, layout properties like border and margin do not inherit, preventing layout chaos.

3. Lab: Environment Setup

To keep our concerns separated, we will not write CSS inside our HTML files. We will create an external stylesheet and link it to our document.

Step-by-Step Configuration

  1. Workspace Preparation: Open your CV project repository from Week 1 in VS Code.
  2. Create the CSS File: In the root directory, alongside index.html, create a new file named styles.css.
  3. Link the Stylesheet: Open your index.html file. Inside the <head> tag, add the following link element to bind the HTML document to the CSS rule engine: 
    <!-- Binds external CSS to the HTML document -->
<link rel="stylesheet" href="styles.css">
  4. Verify Connection: Open styles.css and write a temporary rule: body { background-color: red; }. Start your Live Server. If the screen turns red, the linkage is successful. Delete the temporary rule.

4. Lab: Guided Coding

We will now style the semantic CV document constructed in Week 1, configuring clean navigation headers and establishing professional typography[cite: 1].

Step 1: The CSS Reset & Body Typography

Different browsers apply different default margins and paddings. A "CSS Reset" nullifies these defaults, giving us a blank canvas.

Write the following in your styles.css:

/* 1. CSS Reset & Base Inheritance */
* {
    margin: 0;
    padding: 0;
    box-sizing: border-box; /* Includes padding and borders in the element's total width */
}

body {
    font-family: 'Segoe UI', Tahoma, Geneva, Verdana, sans-serif;
    line-height: 1.6;
    color: #333333;
    background-color: #f4f7f6;
    padding: 20px;
}

Step 2: Styling the Navigation Header

We will use element and descendant selectors to style the header and its internal list navigation[cite: 1]. Notice how we strip the default bullet points from the <ul>.

/* 2. Header and Navigation Typography */
header {
    background-color: #2c3e50;
    color: #ffffff;
    padding: 2rem;
    text-align: center;
    border-radius: 8px;
    margin-bottom: 2rem;
}

header h1 {
    font-size: 2.5rem;
    margin-bottom: 0.5rem;
}

header p {
    font-style: italic;
    color: #bdc3c7;
}

/* Descendant selector: targets ul only inside nav */
nav ul {
    list-style-type: none; /* Removes bullet points */
    margin-top: 1rem;
}

nav ul li {
    display: inline-block; /* Aligns links horizontally */
    margin: 0 15px;
}

/* Pseudo-class selector: :hover */
nav ul li a {
    color: #3498db;
    text-decoration: none;
    font-weight: bold;
    transition: color 0.3s ease;
}

nav ul li a:hover {
    color: #ecf0f1; /* Changes color on mouse hover */
}

Step 3: Section and Article Formatting

Finally, we style the semantic sections and articles. We will add a class to our HTML to demonstrate class selector specificity.

In your index.html, add a class to the Experience article: <article class="cv-card">. Then apply the following CSS:

/* 3. Section and Class Styling */
section {
    background-color: #ffffff;
    padding: 2rem;
    margin-bottom: 1.5rem;
    border-radius: 8px;
    box-shadow: 0 4px 6px rgba(0,0,0,0.05); /* Adds a subtle drop shadow */
}

section h2 {
    color: #2c3e50;
    border-bottom: 2px solid #3498db;
    padding-bottom: 0.5rem;
    margin-bottom: 1rem;
}

/* Class selector: Specificity of 10 */
.cv-card {
    border-left: 4px solid #3498db;
    padding-left: 1rem;
    margin-bottom: 1rem;
}
Debugging Tip: If a style isn't applying, use Chrome Developer Tools (Inspect). Look at the "Styles" tab for the element. If your rule has a line struck through it, it means another rule with higher specificity (or appearing later in the cascade) is overriding it.

5. Classwork

Since your Capstone revolves around an Agile Task Board, managing state via CSS classes is essential. Your task is to apply styles to a "Kanban Task Card" based on specificity rules.

The HTML Structure:

<article class="task-card urgent">
    <h3>Setup Database Schema</h3>
    <p>Configure PostgreSQL tables for users and tasks.</p>
</article>

The Task:

  1. Write a base CSS rule for the .task-card class that gives it a white background, black text, 15px padding, and a standard gray border.
  2. Write a chained class selector (.task-card.urgent) that increases the specificity. For this rule, change the background color to a light red, and the border to a bold, solid red. This proves that the .urgent state overrides the base state due to higher specificity calculation (score: 20 vs 10).

Execute this in your styles.css and preview it in Live Server to verify the override logic.
